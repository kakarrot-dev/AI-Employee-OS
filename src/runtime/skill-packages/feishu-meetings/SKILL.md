# 飞书会议办理

## 适用边界

仅使用本次已授权的三个会议工具。以当前连接用户身份办理。首次会议不需要其他资料员工协作。

1. 依据总管确认的目标确定主题、开始时间、结束时间和收件人。时间使用含时区的 ISO 8601；参考任务提供的当前时间，禁止猜测年份。缺少必要信息时说明缺口，不得创建测试会议。外部好友不在姓名搜索范围内，明确告知可手动转发入会链接；不承诺发送成功。
2. 对每位需要邀请的人调用 feishu.contacts.search@feishu-meetings/v1，参数仅 query。可按不同姓名重复搜索，最多十次。仅使用实际搜索结果中的 openId；同名或 hasMore 时告知用户需核对身份，不可擅自向全部候选人发送。
3. 调用 feishu.meetings.create@feishu-meetings/v1，参数严格为 topic、startTime、endTime、recipientIds。最多十位联系人；用户明确仅创建会议或仅本人参会（例如“就我自己”）时 recipientIds=[]，不搜索“用户本人”，不要求给本人发消息；只有明确要求向自己发送邀请时才查找本人。必须覆盖用户明确要求邀请的人，不能用空名单绕过查找失败。不需要接收方时不得自行搜索或邀请。创建前 Runtime 会展示具体主题、时间和名单，等待用户确认。
4. 返工先读取同次任务会议动作及确认记录，复用已创建的预约及已发送回执；没有剩余工具时直接补充结果说明。取得创建成功的 reserveId、meetingNumber、meetingUrl 后，逐人调用 feishu.meetings.send_invitation@feishu-meetings/v1，参数仅 reserveId、recipientId。消息内容由 Runtime 绑定真实会议结果，发送前等待用户确认。禁止自编会议号、链接、密码、联系人身份或成功消息。
5. 创建失败、拒绝或结果待核实时不得再次创建；发送失败时保留已经创建的会议及已发送名单，不重新创建会议，不声称所有人已收到。结果不确定时请用户在飞书核实，禁止自动重发。
6. 最终分别报告会议创建和逐人发送结果。会议号是九位入会号码；reserveId 是预约标识，不能称为开会后的 meeting ID。邀请发送不代表送达、阅读、接受或实际参会。本能力不创建日历日程、不检查忙闲、不管理会后纪要。时间为邀请中约定的北京时间，endTime 同时是会议号到期时间。未授权的修改、取消等需求说明当前能力边界。

输出保留创建及发送的 ToolAction 证据引用，明确任何未完成邀请和人工处理建议。
