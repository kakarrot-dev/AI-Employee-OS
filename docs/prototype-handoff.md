# 客户端原型开发交接

## 使用方式

当前分支：`codex/client-prototype`。先按照根目录 README 安装或启动原型，再对照本文件验收交互。界面事实源是 `src/renderer/src`，共享样式来自 `prototypes/macos-client-v2/src`。当前不包含可运行后端。

点击标题栏“交互原型 · Mock”切换下一次操作的演示场景，或恢复初始样例。初始四个会话包含空白、成功、失败和待审批状态。

## 页面与交互

| 模块 | 可演示内容 | 数据位置 |
| --- | --- | --- |
| 消息 | 新建与删除会话、输入与附件、流式回复、事项定位与详情、运行进度、失败重试、需求变更、审批确认与拒绝、交付预览与下载 | mock/client.ts 的 conversation、task、attachment |
| 通讯录 | 专家与专家团列表和详情、招募目录、三步创建专家、设置自动保存、解雇、关联能力跳转 | mock/client.ts 的 employee、expertGroup |
| 能力 | Skill / Tool 只读目录、指令与依赖、关联员工、高级信息与状态探测反馈 | mock/fixtures.ts 的 catalog、capabilities |
| 连接 | 应用目录、飞书模拟授权、模拟失败与重试、断开连接；其他应用保持待接入展示 | mock/client.ts 的 connection |
| 系统 | 个人资料、通用、总管指令、模型服务、资源权限、记忆确认和治理、用量与诊断 | mock/client.ts 与原客户端本地偏好 |

候选目录中的未招募对象保持当前设计的不可调用状态；这不代表真实招募或部署已实现。能力目录沿用客户端只读规则，不增加新的管理后台。

## 任务状态契约

| 状态 | 触发 | 界面反馈 | 下一步 |
| --- | --- | --- | --- |
| 正常完成 | 选择正常场景并发送消息 | 回复流、员工进度、交付结果 | 预览/下载示例文件，继续对话 |
| 执行失败 | 选择失败场景，或重新打开中断的任务 | 失败提示和重试入口 | 按原事项重试，原型重试进入成功路径 |
| 等待审批 | 选择审批场景 | 需要确认文件操作 | 确认后完成，拒绝后取消 |
| 需求变更 | 运行中补充要求并提交变更 | 待处理变更 | 接受新要求或保持原事项后继续 |
| 回复取消 | 回复生成期间点击取消 | 停止尚未完成的模拟回复 | 保留用户消息，可继续输入 |
| 直接回答 | 选择直接回答场景 | 回复文字，不创建事项 | 继续讨论 |

全部结果由计时器和固定数据产生，无 Agent 调度、模型推理、联网检索、工具执行或真实第三方授权。文件操作展示模拟位置，不写入业务工作目录；下载只导出明确标注的示例文件。

## 开发接入时的分工

- 界面组件保留交互状态与展示职责。
- `src/shared` 保留界面数据类型和字段校验，名称中的 Runtime/Provider 仅用于兼容已有界面数据契约。
- `src/renderer/src/mock` 是唯一模拟数据实现，可以整体替换为正式的客户端数据适配层。
- `src/main/index.ts` 仅提供 Electron 窗口，不得重新引入业务服务；真实业务实现应在产品开发分支推进。
- `npm run check:boundary` 防止后端目录、依赖、导入及安装包残留重新进入此分支。
