# 数字员工前后台 v0.1 功能需求规格

版本：v0.1 最小闭环评审稿  
日期：2026-09-08  
适用对象：产品、设计、开发、测试及会议业务负责人

本稿已细化客户端页面结构、表单与自然语言协同、状态显示及页面验收。页面结构见第 7.1 节，交互职责和表单规则见第 7.4 节；均为目标需求，不代表当前客户端已实现。

## 2026-09-17 前台范围调整

前台产品名称为“西亚斯数字员工”。左侧整合品牌、新对话、专家市场与聊天记录，不再单列消息菜单或顶部新建会话按钮，底部头像与姓名打开用户菜单，包含个人中心和归档对话；侧栏支持在所有页面折叠。顶部展示当前页面或会话标题及聊天对象，空会话显示“新对话”。侧栏折叠与页面切换保留当前草稿，从任意页面点击“新对话”均进入新的助理空会话；聊天记录在所有页面保留，点击直接打开已有会话。

当前前台优先实现单智能体选用与直接对话，暂不纳入事项、业务场景及专家团。当前 Web 原型交互以 [单智能体前台契约](../prototypes/macos-client-v2/SINGLE_AGENT_V01.md) 为准：默认页和新建会话均与助理聊天；用户也可通过专家市场或助理空会话的“找专家聊天”选择专家。前台面向高校学生与教职工，隐藏能力和连接菜单，专家市场取消左侧对象列表，沿用原招募页卡片布局。保留学科辅导、游戏攻略、旅游出行、恋爱交流、情绪陪伴、校园成长 6 类、20 位学生智能体，新增教学备课、学生指导、科研支持、校务办公 4 类、12 位教职工智能体。Web 目录、详情与聊天身份使用统一校园演示目录，不修改正式客户端的企业专家目录。用户从卡片详情点击“开始对话”，无需招募或配置。每个会话绑定助理或一位专家，草稿、附件与消息按会话独立保存。

默认新会话使用助理欢迎页：姓名问候、居中输入框、学习辅导 / 备课办公 / 旅行攻略 / 聊聊心事快捷提问，以及专家入口。快捷提问只填入输入框并保留已有草稿和附件；首次发送切回正常聊天布局，空会话仍不进入历史记录。原型说明降为页脚提示。

专家市场分类入口提供全部、学生常用、教职工常用、我创建的，支持进一步按用途分类并叠加关键词搜索。切换范围保留关键词、重置用途分类；详情返回保留筛选条件，无匹配可恢复全部。分类仅用于浏览，不构成身份或权限限制。

聊天记录中的操作改为“归档”，归档后从列表移除，但保留消息、附件与草稿。用户从底部菜单进入“归档对话”，可搜索、恢复或删除；恢复回到原会话继续聊天，删除需确认且无法撤销，其他会话不受影响。当前仍是本地原型演示，刷新重置。

消息列表仅展示已有消息的会话。默认或新建的空会话不新增卡片，历史记录不高亮；输入草稿或选择附件不入列，首次发送文字或附件后才显示并选中该会话。

专家市场开放“创建专家”，改为独立页面，复刻后台当前单专家编辑器的四个分区：基础与提示词、模型配置、执行能力、输入输出，并提供实时对话预览。名称 2–20 字符，简介必填且最多 200 字，系统提示词必填且最多 8000 字；开场白与推荐问题选填。可配置模型、输出 Token、超时、流式与生成参数，添加 Skill / Tool / MCP 的版本和具体操作，多选输入输出格式。前台能力账号固定使用者本人、资料限定本人可访问范围，写入和发送由本人确认；知识库仍为敬请期待，后台发布治理不在前台开放。

创建草稿跨页保留，取消清空；校验失败切至对应分区。创建成功加入“我创建的”并进入独立聊天，开场白与推荐问题用于对话起始页，详情展示全套配置。自建资料和对话均为本次页面中的演示数据，刷新重置，尚未连接模型、工具执行或文件生成服务。模型与能力选项沿用后台 2026-09-17 演示目录快照，不代表两端服务已打通。

前台不再提供独立系统设置，左下角用户菜单提供“个人中心”及“归档会话”快捷入口。个人中心包含“基本资料 / 归档会话”两项菜单，默认进入基本资料，展示头像、姓名、学号、Token 总用量、积分余额和用量记录；归档会话复用搜索、恢复和确认删除流程。仅头像可上传，姓名和学号只读；学号暂用明确标注的示例值。不提供其他系统设置分栏、预算编辑及预算余额，不展示模型名称或模型明细。

用量记录按时间倒序分页，每页 10 条，展示当前范围、总条数和页码，提供上一页 / 下一页并在首末页禁用越界操作。Token 总用量按全部记录计算，积分余额单独展示；记录包含每次 Token 用量和消耗积分，不展示人民币金额，切页不影响概览值。当前积分余额与消耗均为独立的示例数据，不定义兑换比例。

下文的事项、专家团、会议场景和总管统一编排要求保留为此前方案，不再作为当前前台实现与验收要求。后台与 Runtime 的既有设计和实现未随本次原型调整变更。

## 1. 摘要与范围决定

**v0.1 只打通“后台创建专家和专家团 → 发布到数字员工前台 → 用户选用 → 完成一次会议场景”的闭环。**

已确认分工：后台决定专家和专家团的配置、使用范围及业务规则；前台负责发现、选用、沟通、确认、处理和结果展示。使用范围的完整管理能力后续建设，v0.1 不建设用户和权限系统。

| 前台称谓 | 产品对应 | 本期处理 |
| --- | --- | --- |
| 总管／数字助理 | 用户的统一沟通入口 | 本文统一称数字助理 |
| 专家 | 专家智能体和业务智能体 | 后台创建，前台按用途展示和使用 |
| 专家团 | 业务场景 | 后台组合并配置，前台作为整体业务选用 |
| 专家团的协调角色 | 场景智能体 | 后台为专家团配置一个，不增加独立前台聊天入口 |

**本期不做：**

- 用户管理、组织部门同步、账号生命周期、角色权限配置、按人授权、权限审查和失权交接系统。
- 业务监控、跨事项运行中心、审计查询、聊天风险监控和统计大盘。
- Token 监控、用量报表、费用统计和预算管理。
- 其他业务场景、自由流程编排、完整能力市场、多租户及多终端扩展。

本期保留单次会议的进度、确认、失败提示及结果依据，这是完成会议的必要交互，不要求建设业务监控模块。会议服务本身必需的连接及第三方授权属于接入条件，不等于建设本产品用户权限系统。

本文取代上一版前台功能稿的 v0.1 范围。其他规划文档和 PM 工作台需求中的更广平台要求只作为后续参考，不能据此追加本期用户权限、监控或预算验收。本文只写产品功能与交互，不规定代码、接口、数据库或 Agent 运行方案。

## 4. 目标与成功标准

1. 后台可以实际创建并保存会议需要的专家。
2. 后台可以创建专家团，选择协调角色与业务专家，保存业务规则并发布。
3. 前台读取同一份已发布内容，无需再次手工创建或维护另一套专家与专家团。
4. 用户在前台选用该专家团，补充信息、确认并完成一次会议业务。
5. 前台显示真实会议结果、阶段状态、必要人工处理及最终完成依据。

只保存配置、展示固定卡片、播放预设状态或生成会议链接，均不能单独证明整条闭环完成。不以账号权限覆盖率、业务监控数据或 Token 指标作为本期验收条件。

## 5. 使用者与试用条件

| 业务参与者 | 本次会议中的动作 |
| --- | --- |
| 发起人 | 提出目标、确认方案、处理异常、确认结论和最终验收 |
| 参会人 | 对本次会议接受或拒绝，提供必要反馈 |
| 行动项责任人 | 查看本次要求、提交结果 |
| 后台配置人员 | 创建专家和专家团、检查并发布 |

- 使用固定试用参与人和已准备好的会议服务连接，不以学校全量身份同步为前提。
- 保留本次会议必要的人员标识和动作来源，避免把发起人操作误称为参会人本人确认。
- 可沿用既有身份或会议服务提供的身份与反馈渠道，不为参会确认新建本产品账号体系。人工代录必须标明记录人和实际反馈来源，不能冒充本人在线操作。
- 本期发布对象在约定试用环境内统一可用，不配置逐人、逐部门的可见范围。
- 专家是否可独立选用属于对象用途配置：专家智能体可独立使用，业务智能体用于专家团；这不要求建设用户权限系统。
- 首期采用单次、校内、纯线上 Teams 会议。周期会议、校外匿名参会和线下会议室不纳入。

## 6. 用户价值

后台配置一次，前台即可选用；用户通过数字助理完成会议，不必理解专家配置。办理中能看见当前步骤、等待谁、有什么结果及如何继续，避免在多个独立演示中重复录入同一业务。

本期不承诺未经验证的效率提升比例或平台治理收益。

## 7. 功能与交互方案

### 7.1 最小页面范围

| 侧别与入口 | 本期功能 | 边界 |
| --- | --- | --- |
| 后台智能体中心 | 专家列表、创建、详情、编辑、检查及启用 | 一套对象流程，不做按人授权 |
| 后台业务中心 | 专家团列表、创建、详情、编辑、检查及发布 | 一个场景智能体、多个业务智能体，不做自由拖拽编排 |
| 前台通讯录 | 专家、专家团列表、搜索、详情、选用 | 读取后台发布内容，不另建配置 |
| 前台消息 | 数字助理沟通、输入、方案、会议事项、必要处理卡及结果 | 会议主操作区 |
| 前台事项边栏 | 本次会议节点、责任、进度和结果依据 | 不扩展为跨事项业务监控 |
| 能力、连接、系统等既有页面 | 保留既有基础，会议所需服务可预配置 | 独立完整度不作为验收条件，不新增用户权限、监控或用量页面 |

本期不要求重做其他页面；已有非本期入口可保留现状，其完善不列入本期任务。前台的组织专家创建、发布、解雇和模型配置不属于本次使用流程；配置统一在后台维护。这是页面职责划分，不增加角色权限系统。

#### 7.1.1 客户端整体布局与页面关系

保留“消息、通讯录、能力、连接、系统”五个一级入口，不另设首页、业务中心、审批中心或监控中心。启动进入消息；数字助理是用户沟通对象，专家与专家团是选用的能力，不为每个专家另开聊天产品。

```text
客户端窗口
├─ 左侧一级导航：消息、通讯录、能力、连接；底部系统
├─ 当前模块上下文区：列表、分类或设置分区
├─ 主内容区：对话、对象详情或设置内容
└─ 消息页按需展开右侧事项边栏

消息
├─ 会话列表 → 对话时间线 + 常驻输入区
├─ 时间线中的信息表单、选择卡、确认卡、处理卡、结果卡
└─ 事项卡 → 右侧事项详情 → 定位对应处理卡
通讯录
├─ 专家列表 → 专家详情 → 使用专家 → 消息
└─ 专家团列表 → 专家团详情 → 使用专家团 → 消息
能力 → 既有只读能力目录及说明
连接 → 服务状态与必要连接处理
系统 → 既有个人偏好与客户端说明
```

消息页展开边栏后仍能看到对话和输入区；窄窗口可收起上下文列表，不能以挤压表单主操作或遮挡确认按钮换取四栏常驻。普通详情沿用当前客户端展示容器，不要求新建独立窗口。

#### 7.1.2 PAGE-01 消息页

| 区域 | 展示内容 | 用户操作与结果 |
| --- | --- | --- |
| 会话列表 | 会话名称、最近消息摘要、更新时间；当前会话选中态 | 新建会话、搜索、选择历史；仅切换上下文，不取消进行中的会议 |
| 对话标题区 | 当前会话名称、数字助理身份、当前选择的专家或专家团 | 查看所选对象说明；准备阶段可更换选择，已有事项不随之更换专家团 |
| 消息时间线 | 用户消息、数字助理回复、补充表单、方案和处理卡、事项卡、结果 | 阅读、填写、选择、确认；卡片动作结果留在原事项上下文 |
| 事项入口 | 事项名称、所属专家团、当前步骤、状态、等待对象或下一步 | 查看事项打开右侧边栏；有多个事项时明确每张卡对应哪个事项 |
| 输入区 | 多行文字、发送、附件、已选专家或专家团提示 | 输入目标或修改要求；Enter 发送、Shift+Enter 换行，中文输入法选词不误发送 |
| 附件区 | 待发送文件名称与状态、失败原因 | 发送前移除，失败后重新选择；历史材料按既有能力打开，不新增文件格式 |
| 处理反馈 | 回复处理中、动作提交中、回复失败或服务异常 | 提交中防重复；停止回复只结束回复生成，不等于取消会议 |

空会话显示数字助理说明、输入区和“从通讯录选择专家或专家团”入口，不显示虚构的历史会议或执行进度。无搜索结果与没有历史会话分别提示。回复失败保留用户输入，业务动作失败显示该动作的恢复方式，不用“重新发送整段对话”代替业务恢复。

会话承载沟通，事项承载本次会议业务。新建会话不创建事项；一条会话可沿用既有多事项能力，本期只要求完整走通一次会议，不新增多事项管理系统。

#### 7.1.3 PAGE-02 通讯录列表

| 区域 | 展示内容 | 用户操作与结果 |
| --- | --- | --- |
| 分类与搜索 | 专家、专家团两个分类；当前分类搜索框 | 搜索名称和说明；分类与输入改变仅过滤目录，不修改发布配置 |
| 专家条目 | 名称、职责摘要、用途、可用状态 | 选中查看详情；业务专家标明“用于专家团” |
| 专家团条目 | 名称、业务目标摘要、可用状态 | 选中查看详情，不因单击条目就开始会议 |
| 加载与异常 | 加载中、尚无发布内容、无匹配结果、读取失败 | 失败提供重新加载；空目录说明需由后台创建并发布 |

目录使用后台已发布内容。前台不提供创建、编辑、发布、解雇或调整组织专家团成员的入口；如保留既有“招募”入口，只用于浏览同一发布目录，不另建安装或授权流程。

#### 7.1.4 PAGE-03 专家详情

展示名称、职责、用途、适用任务、所需输入、预期输出、限制及当前可用性；仅供专家团使用的业务专家同时展示所属已发布专家团。没有配置的说明显示未提供，不由前台补造能力承诺。

- 专家智能体：提供“使用专家”，进入消息并显示所选专家，等待用户表达目标。
- 业务智能体：说明“通过专家团使用”，提供对应专家团入口，不提供独立执行按钮。
- 暂不可用：显示原因，禁用使用；历史结果仍按原事实保留。
- 不展示可编辑的提示词、模型、能力绑定或生命周期表单。

#### 7.1.5 PAGE-04 专家团详情

| 区域 | 必须展示的内容 |
| --- | --- |
| 基本信息 | 名称、业务说明、当前可用性 |
| 输入与产出 | 用户需要准备什么、最终得到什么 |
| 成员职责 | 协调角色及业务专家分别负责什么；只读展示 |
| 业务流程 | 已发布业务节点、需要人工参与的步骤 |
| 完成规则 | 哪些结果和确认满足后才算完成 |
| 主操作 | 使用专家团；不可用时显示原因并禁用 |

点击“使用专家团”进入消息准备上下文，数字助理收集本次输入，不创建会议。用户从通讯录发起新的选用时进入新的准备上下文；沿用现有会话容器，不覆盖既有事项。用户在消息中明确继续某个已有事项时回到该事项，不另建重复事项。准备阶段更换专家团时提示原输入哪些仍适用，不能悄悄迁移已确认业务。

#### 7.1.6 PAGE-05 事项边栏

事项边栏属于消息页，不是独立业务监控页面。

| 区域 | 展示内容与操作 |
| --- | --- |
| 概要 | 会议名称、专家团名称、目标、当前事项状态 |
| 节点进度 | 全部业务步骤、每步当前状态、当前责任或等待对象；未开始步骤明确标记 |
| 当前待处理 | 需要做什么、谁处理、期限（有约定时）；点击定位时间线对应表单或处理卡 |
| 方案与变更 | 当前有效方案、已确认内容及关键变更摘要；历史只读，不覆盖旧确认 |
| 阶段结果 | 已创建会议、通知情况、结论和行动项；分别展示部分成功与未完成部分 |
| 最终结果 | 完成条件满足情况、结果文件或外部链接、必要依据及验收记录 |
| 收起操作 | 收起边栏并回到原对话位置，不取消、暂停或重置事项 |

边栏以查看和定位为主，编辑与确认在消息卡完成，避免两处独立表单互相覆盖。同一事项的消息卡、边栏和结果卡必须展示一致状态。

#### 7.1.7 PAGE-06 能力、PAGE-07 连接、PAGE-08 系统

| 页面 | 结构和可保留操作 | 本期边界 |
| --- | --- | --- |
| 能力 | 既有 Skill、Tool 分类目录及只读详情，可搜索并查看用途和可用性 | 不复制专家团目录，不要求用户手动绑定工具才能使用会议；不新增上传、编排或市场功能 |
| 连接 | 服务卡片、状态、必要连接说明；会议使用的服务可查看当前是否可用，必要时进入既有或外部授权流程 | 候选卡片不能表示已经接通；可预配置，不要求交付完整连接管理页 |

现有系统分区名称包括个人资料、通用、总管、模型服务、资源与权限、记忆与存储、用量与预算、关于与诊断。列出名称仅用于定位现有页面，不表示本期需要完善这些模块，也不要求统一重命名；“总管”在产品含义上即数字助理。会议所需基础配置可由项目人员提前完成，用户办理时不应被引导配置模型、提示词或平台权限。

### 7.2 后台创建专家

**B01 专家配置与启用**

| 配置内容 | 要求 |
| --- | --- |
| 名称与说明 | 名称用于选用和引用，说明表达职责及适用任务 |
| 用途 | 专家智能体、场景智能体或业务智能体，保持同一对象流程 |
| 工作规则 | 提示词中的职责、输入、处理、输出及异常约定 |
| 必要能力 | 从已准备好的真实 Skill、工具或连接中选择，不要求建设完整能力管理平台 |

操作：新建 → 填写 → 保存草稿 → 检查及试用 → 查看结果 → 启用。

- 缺少名称、用途、工作规则或必要依赖时定位问题，不能伪装为可用。
- 保存后在列表和详情能找到同一专家，再次打开可继续编辑。
- 草稿不进入前台可用目录，业务智能体不出现独立使用入口。
- 会议所需能力和模型可预配置，但名称占位或固定模拟结果不能替代实际可用能力。
- 完整版本回滚、复制、删除及批量管理不作为本期独立功能要求。

### 7.3 后台创建专家团

**B02 专家团配置与发布**

| 配置内容 | 要求 |
| --- | --- |
| 名称与说明 | 例如校内会议，说明目标及最终产出 |
| 场景智能体 | 选择一个，承担该专家团业务协调职责 |
| 业务智能体 | 选择一个或多个，完成会议所需工作 |
| 业务规则 | 会议输入、步骤、责任、必要确认、异常及完成条件 |
| 发布状态 | 区分草稿与前台可使用的已发布内容 |

操作：新建 → 填写基本信息 → 选择协调角色和业务专家 → 核对规则及关系 → 保存 → 检查并试用 → 发布。

- 成员选择支持搜索；协调角色单选，业务专家多选，搜索不清空已有选择。
- 业务中心引用场景智能体的工作规则，不维护第二份独立场景提示词。
- 可以采用预设会议节点模板，不要求开发任意场景编排器。
- 引用对象缺失、用途错误、成员关系不一致或会议依赖不可用时不能发布，页面说明具体问题。
- 发布后前台能读到名称、说明、成员、节点和完成规则；未发布修改不直接改变前台使用内容。
- 修改并重新发布后，新事项采用新内容；已开始会议保留原约定，不改写历史。
- 不填写试点用户列表、部门范围或角色授权，不以用户目录同步作为发布前提。

### 7.4 前台发现、选用与沟通

**F01 通讯录**

- 保留专家、专家团两个分类，按名称与说明搜索。
- 专家详情展示职责、输入输出及使用方式；专家团详情展示业务目标、成员、步骤和完成条件。
- 专家团即业务场景唯一目录，不另建重复业务中心。
- 点击使用专家或使用专家团进入数字助理会话，明确显示当前选择；选择本身不创建正式会议或向外发送信息。
- 列表、搜索和详情使用同一份后台发布内容；加载失败明确提示重试，不回退为看似已配置的固定演示数据。
- 暂不可用对象说明原因，不显示可执行的虚假按钮。

**F02 消息与输入**

- 用户可以直接表达会议需求，也可先选专家团；已明确选择的专家团不被静默替换。
- 数字助理收集缺少的必要信息，在消息中展示表单或补充问题；已有信息先填入供核对。
- 支持既有文字和附件操作，不新增格式要求；解析失败定位到材料并保留可恢复输入。
- 普通问答不产生会议副作用；停止生成回复与取消会议分别表达。
- 不要求扩展多会话管理、记忆或普通聊天质量体系来通过本期会议验收。

#### 7.4.1 提示词、业务规则与客户端的职责

**客户端必须支持真实可操作的表单和卡片，不能只把提示词生成的文字排成表单样式。** 不开发通用表单设计器，先支持会议需要的有限控件与动作。

| 内容 | 专家团规则及数字助理负责 | 客户端交互负责 |
| --- | --- | --- |
| 收集信息 | 根据业务规则识别缺项、整理问题、提取用户已提供内容 | 展示预填表单、必填提示、选择控件、校验及提交结果 |
| 选择方案 | 提供有依据的候选方案、说明差异 | 展示可点击的单选或多选项、当前选择及确认操作 |
| 自然语言修改 | 理解“改成一小时”等修改意图，定位本次事项 | 同步表单与方案，突出修改内容；歧义时等待澄清 |
| 确认动作 | 说明要做什么、涉及谁和影响 | 展示确认卡、提交状态、拒绝或修改入口及确认结果 |
| 进度与结果 | 提供处理说明、结果摘要及下一步建议 | 依据实际业务结果展示状态，不能因回复出现“完成”而标记成功 |

字段范围、必填条件和业务校验遵循发布的专家团规则或本期固定会议模板。数字助理可按缺失信息组合展示已支持字段，不能随意新增要求或通过自然语言绕过确认。表单暂不可用时可保留澄清对话，但不得把需要确认的外部动作自动执行；本期验收不能用纯文字问答替代表单与确认卡。

#### 7.4.2 会议信息表单与有限控件

| 字段 | 控件 | 核对与校验规则 |
| --- | --- | --- |
| 主题、会议目标 | 单行文本、多行文本 | 必填，不能为空；已从对话识别则预填 |
| 参会人 | 人员多选及搜索 | 从约定试用人员或已连接服务的实际候选中选择，不建设人员管理系统；重名展示区分信息 |
| 必到人员 | 从已选参会人中多选 | 必须属于参会人集合；移除参会人时同步提示必到集合变化 |
| 时间范围 | 日期时间选择 | 必填，结束晚于开始，明确显示时区；相对时间转换为具体日期供确认 |
| 时长 | 数值或预设单选 | 必填正数，满足会议业务限制；与时间范围冲突时提示调整 |
| 是否录音转写 | 是／否单选 | 明确选择，不把用户未回答当作同意；选否时说明对会后材料的影响 |
| 期望产出 | 已支持产出的多选，必要时补充文字 | 按会议规则选择；额外文字不自动扩大业务能力或取消固定完成条件 |
| 候选会议时间 | 候选卡片单选 | 展示具体起止时间及冲突说明；无可用候选时给出调整入口 |

填写区提供“确认信息”和继续用文字补充的入口。确认信息仅完成输入核对，随后展示会议方案；“确认方案并发起”才形成正式事项。无效字段就地提示并定位，不能只在页面顶部显示笼统失败。

#### 7.4.3 表单与自然语言共用同一份业务信息

1. 用户说“下周安排项目评审，张三和李四必须参加”，数字助理预填已识别内容，要求补充具体可选时间、时长等缺项。
2. 用户可操作表单，也可说“改成一小时”；时长、方案摘要和后续确认展示均同步为 60 分钟。
3. 有多个事项或指代不明时先明确修改对象，不修改错误会议。用户手动填入但未提交的内容不能被后到回复静默覆盖；有冲突时展示差异供用户决定。
4. 确认前的修改更新当前草稿；确认后的关键修改形成新方案，相关旧确认失效。历史表单及确认卡只读，并提供查看当前方案的入口。
5. 所有表单、选择卡和确认卡都绑定当前事项或准备上下文。重新打开时恢复当前有效内容与状态，不能重新提交历史动作。

#### 7.4.4 消息卡片种类及提交状态

| 卡片 | 内容与操作 | 完成后的显示 |
| --- | --- | --- |
| 信息表单 | 字段、必填说明、错误和确认信息 | 已确认输入摘要，可返回修改当前草稿 |
| 方案选择卡 | 候选时间或方案、差异、选择及确认 | 当前选择和后续方案，不直接创建会议 |
| 方案确认卡 | 目标、时间、人员、流程、影响、完成条件；确认方案并发起或修改 | 本次已确认方案及事项入口 |
| 责任／动作卡 | 接受或拒绝、具体动作确认、结论确认、行动项提交 | 处理结果、实际处理来源及时间；重复操作不可再次生效 |
| 结果／验收卡 | 阶段产物、部分失败、依据、完成条件；符合条件时提供最终验收 | 完成结果或待处理缺项，不用一句成功文案覆盖失败部分 |

可编辑、校验未通过、提交中、提交失败、已提交、已失效是交互状态，不是新的业务状态。提交失败保留输入；可安全重提时才给出重试；外部结果未知时展示核实路径。提交中禁用重复提交；旧卡失效后明确原因并定位最新版。

### 7.5 会议主线与责任动作

**F03 会议方案、处理与完成**

| 步骤 | 前台展示 | 操作及结果 |
| --- | --- | --- |
| 1. 补充信息 | 主题、目标、参会人、必到人员、时间范围、时长、录音转写意愿、期望产出 | 发起人补充或纠正；人员标识需明确，不凭重名猜测 |
| 2. 核对方案 | 忙闲结果、可选时间、人员、步骤及影响 | 无共同时间先调整；发起人确认方案后形成正式事项 |
| 3. 参会确认 | 各参会人的实际反馈及等待对象 | 必到人员分别确认；拒绝或超时不视为同意，不满足条件不创建会议 |
| 4. 创建会议 | Teams 会议结果、加入链接、通知结果 | 核对外部结果，分别显示会议创建和通知送达情况 |
| 5. 会后材料 | 录音、转写、缺失材料及歧义 | 补充或核对，不虚构会议内容 |
| 6. 确认结论 | 结论草案、依据及待确认项 | 发起人确认或提出修改 |
| 7. 行动项 | 责任人、要求、期限、提交及 Planner 同步状态 | 责任人提交结果；提交成功与同步成功分别表示 |
| 8. 最终验收 | 结论、行动项、送达及证据汇总 | 全部条件满足后发起人验收，事项显示完成 |

- 每张处理卡显示本次事项、待处理内容、处理人、当前方案或结果、动作影响及状态。
- 实际确认人与反馈来源需可核对，不要求建设通用权限配置或待办平台。
- 重复点击不重复创建会议或提交同一动作；已处理卡片显示结果，不重复执行。
- 方案确认不替代参会人反馈及业务要求的具体动作确认。
- 只有结论确认、全部行动项完成并同步、相关人员收到结论、发起人验收且证据齐备，才算本次会议业务完成。
- 不将会议链接生成、邀请发送、对方接受和单个行动项完成相互替代。

### 7.6 单次事项进度、变更与异常

**F04 事项交互**

- 消息卡展示当前会议、节点、状态及下一步；边栏查看业务节点、责任、阶段结果及依据。
- 保留单次事项的真实记录用于继续办理和核对，不建设后台跨业务列表、审查中心、统计或告警。
- 关闭边栏或离开页面不取消会议；恢复查看时以实际办理结果为准，不重置为初始状态。
- 事项可显示等待用户、执行中、已完成、执行失败、结果未知、已取消；等待用户需注明等待谁。节点是业务过程，不用专家名字或思考中动效替代。
- 修改时间、必到人员等关键内容时展示差异，使相关旧确认失效并重新确认；历史方案和已发生结果保留。
- 申请取消前说明已有会议和受影响人员；用户确认取消申请不等于外部取消已经成功。

**业务步骤与状态分别展示。** “创建会议”是步骤，“结果待核实”是该步骤的解释性状态。事项总体状态仍使用前述固定口径；节点状态沿用既定业务规则，前台不自行增加同义状态或根据提示词文本推进。点击确认表示已提交决定，只有实际结果成立后才显示对应节点完成。该要求属于单次事项交互，明确纳入 v0.1。

| 情形 | 触发与影响 | 恢复交互 | 保留结果依据 |
| --- | --- | --- | --- |
| 信息缺失 | 不允许确认方案 | 定位缺项，补充后继续 | 本次输入与补充 |
| 无共同时间 | 不创建会议 | 调整时间或人员 | 原约束与新方案 |
| 拒绝或超时 | 受影响步骤不继续 | 发起人等待、调整或取消 | 实际反馈、期限及新确认 |
| 服务不可用 | 无法完成相关动作 | 说明原因，恢复后继续 | 失败对象与已完成结果 |
| 结果未知 | 无法确定外部动作是否生效 | 先核查，阻止盲目重复提交 | 原动作及核查结果 |
| 部分成功 | 会议已创建但通知或同步失败 | 保留成功部分，只处理剩余问题 | 会议链接与逐项结果 |
| 材料缺失或歧义 | 无法形成可信结论 | 补充材料或人工核对 | 来源、缺口及确认 |
| 关键变更 | 相关旧确认不再有效 | 展示差异并重新确认 | 前后方案及确认记录 |

该表只规定会议本身的恢复交互，不要求建立通用异常监控平台。

### 7.7 连接与运行前准备

**F05 最小服务可用性**

- 所需模型、能力及 Microsoft 服务可由项目人员提前准备，不要求完整连接管理、模型管理或凭据治理页面。
- Teams 是本次会议必需服务；流程实际使用 Outlook、录音转写或 Planner 时，相应能力必须可用。
- 需要第三方本人授权时沿用已有或外部授权流程，显示成功、失败及取消，不新增本产品登录、注册和权限中心。
- 前台不展示服务密钥；能力不可用时说明原因，不虚假显示已连接或完成。
- 不将 Token 计量、用量图表、费用或预算控制列为本期新需求。

### 7.8 前后台对应与交付证据

| 后台动作 | 前台可观察结果 | 核对方式 |

### 7.9 通用交互与评审项

- 列表和表单覆盖加载、空内容、无搜索结果、错误及保存成功；失败保留可恢复输入。
- 提交显示处理中并防止重复操作，长名称、参会人列表和弹层不遮挡主按钮。
- 保留当前客户端窗口适配与键盘交互基础，不扩大到其他终端。
- 待业务评审的细节：参会反馈采用的既有身份或外部渠道、确认期限、允许零行动项的条件、缺失转写时可接受的替代材料。由会议业务负责人在相关分支验收前确定。
- 用户权限、离岗失权交接、监控指标和 Token 预算不再作为本期评审阻塞项。

## 8. 交付与验收

### 8.1 交付顺序

1. 后台专家创建与启用、专家团创建与发布。
2. 前台读取发布内容，完成发现、详情和选用。
3. 会议输入、方案、确认、执行结果、会后结论及行动项。
4. 完成一次真实会议业务，并验证必要失败恢复。

每一步复用已有可用部分，不因存在某个后台菜单扩大交付范围。排期另行估算，本文不预设工期。
