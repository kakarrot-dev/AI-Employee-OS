# AI Employee OS 架构总览

> 现行入口文档。与根目录 `AGENTS.md` 对齐；冲突时按 AGENTS 事实源优先级裁决。本文不定义 Schema 或接口字段。

## 产品定位

Local-first 的 macOS AI 员工操作系统：客户端负责交互与 Keychain，Rust Runtime 负责状态、权限与 Tool 执行，Python Worker 负责意图、闲聊与规划推理。

当前主验证路径：DeepSeek Key → 编辑员工 Identity / Soul / Persona → 多轮对话 → 意图路由；工作意图按员工已绑定 Skill 的 readiness 进入 Resolver → Generic Run Kernel → ToolExecutor → verified Deliverable。

## 进程边界

```text
Swift macOS Client
  UI、本地 Store、Keychain；不推理、不直接执行 Tool
        |
        v
Thin Rust Runtime
  Task/Action、权限、审批、Tool Gateway、SQLite、事件
        |
        v
Python Agent Worker
  意图分类、闲聊、Context/规划、LLM Provider；不直接取得系统权限
```

硬规则：

- 所有 Tool 调用必须经过 Rust `ToolExecutor`。
- Secret 只经 Keychain 注入受控进程环境；不进入仓库、SQLite、日志、Trace、Memory 或 Agent Context。
- Skill 经 `agent_skills` 绑定到员工；Tool 全局安装（无 per-agent Tool 绑定表）；客户端不创建 Package。
- 进程间通信为 CLI / 子进程 JSON，不是 gRPC。
- 默认工作编排为通用 bounded agent loop，可选 workflow；Rust 是 Task/Run/Action 状态与副作用事实源（ADR-032）。LangGraph / Deep Agents 不是状态源。

## 产品导航

七模块：办公室、通讯录、工作库、知识库、技能库、工具库、设置。知识库当前只读展示 Runtime SQLite 中的 canonical Knowledge 来源与索引状态；本地文件只有经 Runtime 导入后才会进入该页面。页面级事实源见 [Main Interface Spec v2.0](./design-system/AI%20Employee%20macOS%20Main%20Interface%20Spec%20v2.0.md)；视觉 Token 见 [Claude Cream](./design-system/Claude%20Cream%20macOS%20UI.md)。

## MVP 分层

| 层 | 内容 |
|---|---|
| 产品可见 | 多轮对话、员工 Profile、仓库 Package 安装与列表、Skill 绑定、意图路由、Task Inspector |
| Runtime 已有、产品未全暴露 | Task/Run/Action、Snapshot、Checkpoint、Permission、Approval、Audit、Artifact/Deliverable、Memory/Knowledge/Evaluation |
| 暂不包含 | Computer Use、Multi-Agent、Cloud Sync、Marketplace、企业 RBAC、实时网页抓取、公证发行 |

客户端已支持多员工 Profile 的创建、编辑与停用；多员工工作执行尚未成为主验证路径。

# Phase 1 多员工业务流（Release Candidate）

「场景库（暂定）」允许用户手工配置或让受限 AI 协调器提出串行 DAG 草案。确认后由 Rust Runtime 物化 Root Task、Child Task、WorkOrder、Handoff 和 Root 输出绑定；每个 Child 继续复用 Generic Run Kernel。当前最大参与员工 5、WorkOrder 12、并发固定 1；并行调度、员工群聊和全局协调权限不在 Phase 1。
