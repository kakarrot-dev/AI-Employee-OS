# AI Employee macOS UX State & Interaction Standard v1.0

## 1. 文档目的

本文档定义 AI Employee OS macOS 客户端的加载、空白、错误、恢复、表单验证、命令面板、动效和可访问性交互标准。新页面和新组件必须先选择本文定义的状态与行为，不得自行建立另一套反馈语言。

本文档不改变 Runtime、Task、Action、Employee、Conversation、Approval、Artifact、Skill 或 Tool 的业务契约。所有界面状态必须由现有事实派生。

## 2. 适用范围与优先级

适用于办公室、通讯录、连续工作区、工作库、场景库、技能库、工具库、设置和员工编辑器。场景配置采用列表、依赖顺序和 Inspector，不使用自由画布；AI 提案与手工草案共用确认编辑器。

发生冲突时遵循项目根目录 `AGENTS.md` 的事实源优先级。页面结构以《AI Employee macOS Main Interface Spec v2.0》为准，颜色与基础 Token 以《Claude Cream macOS UI》为准，本文只负责交互状态和反馈表现。

## 3. 体验原则

1. 用户在任意时刻都应知道：系统正在做什么、是否需要介入、失败影响了什么、下一步可以做什么。
2. 加载不是空状态。请求结束前禁止显示“没有数据”。刷新时优先保留旧内容。
3. 错误不是一句红字。可恢复错误必须提供作用域明确的恢复操作。
4. 成功反馈不能覆盖失败事实。Task、Action、Approval 和 Artifact 的最终状态只服从 Runtime。
5. 低风险瞬时结果可以使用非阻塞提示；安全、权限、持久化和外部副作用必须保留在上下文中。
6. 动效只用于解释状态变化，不承担信息传递，也不能延迟操作。
7. 键盘、VoiceOver、Reduce Motion、Light/Dark Mode 是完成条件，不是后续优化。

### 3.1 产品语言

界面文字先描述用户目标、可见结果和下一步，再在确有诊断价值时展示实现术语。

- 普通页面不直接展示原始 JSON、内部枚举、错误码、数据库表名或协议字段；这些内容只能进入明确标注的技术详情。
- `Runtime`、`Worker`、`Skill`、`Tool`、`Package` 等术语只在设置、技能库、工具库和诊断区按需出现；普通操作使用“运行环境”“技能”“工具”“已连接”等用户语言。
- 同一动作使用同一动词：办公室“交代工作”，员工“开始对话”，方案“生成 / 确认执行”，记录“归档 / 恢复 / 删除”。
- 按钮描述点击后的直接结果，不描述内部步骤；一次性授权必须写明“允许一次”，不能只写“批准”。
- 原始状态必须经过统一 Presentation 映射，例如 `indexed → 已索引`、`failed → 未能完成`；未知值显示“状态待确认”，不得把原值直接推给普通用户。
- 删除与失败文案先说明用户可见影响，再说明仍保留的证据；不得要求用户理解 `Task / Action / Audit` 才能判断后果。
- 标题和说明各承担一个职责。标题说明对象或动作，说明补充原因、边界或下一步，不重复标题。

## 4. 标准状态模型

每个异步表面只能处于以下一种展示状态：

| 状态 | 进入条件 | 用户可见表达 | 必须提供 |
| --- | --- | --- | --- |
| `idle` | 尚未发起操作 | 正常内容或初始引导 | 下一步主要操作 |
| `loading` | 首次请求且无可展示旧内容 | 局部 ProgressView 和具体动词 | 可访问状态说明 |
| `refreshing` | 有旧内容且正在刷新 | 保留旧内容，局部刷新标记 | 不闪现空状态 |
| `empty` | 请求成功且结果为空 | 原因、对象和唯一下一步 | 与搜索无结果区分 |
| `success` | 操作已由事实源确认 | 更新后的内容；必要时短提示 | 不重复弹窗 |
| `failure` | 操作失败且结果已知 | 失败对象、影响和原因 | 可恢复时提供 Retry |
| `blocked` | Action 等待授权或权限处理 | 明确等待谁处理什么 | 审批或前往设置入口 |
| `result_unknown` | 副作用结果无法确认 | 需要人工核验 | 禁止自动重试 |

Task 不得使用 `blocked`。Task 与 Action 的枚举必须保持 canonical 契约。

## 5. 加载与进度

### 5.1 首次加载

- 使用局部 `ProgressView` 和具体说明，例如“正在读取员工”“正在加载工作记录”。
- 本地短读取不使用全屏遮罩，不人为延长 Skeleton。
- Skeleton 仅适用于布局固定、内容明显且预计等待超过 300ms 的首次加载。

### 5.2 按钮加载

- 触发后禁止重复提交。
- 按钮宽度、字号和高度保持稳定，只替换图标与文案。
- 文案必须包含动作，例如“正在保存”“正在发送”“正在取消”。
- 失败后恢复可点击状态，并在原操作附近显示原因。

### 5.3 任务进度

- 有真实百分比时才使用确定型进度条。
- 无真实百分比时展示当前 Action、已完成 Action 数和总数，不伪造百分比。
- Spinner 只表达短暂且不可计算的局部等待。
- 超过 8 秒的不可预测等待必须展示当前阶段和取消入口，前提是 Runtime 支持取消。

### 5.4 会话回复

- 用户提交后必须立即写入本地时间线，并自动滚动到最新位置。
- 闲聊回复使用 Runtime 转发的真实 Provider 增量事件，禁止用定时器拆分完整文本伪造流式输出。
- 第一个增量事件到达前显示员工名、已处理时间和明确等待文案；到达后在同一节点逐步渲染 Markdown。
- 增量内容只用于当前界面展示。完整回复成功后才作为正式消息写入 SQLite；失败时不得保存半截回复。
- 流式增长期间跟随底部但不播放逐 Token 滚动动画，避免持续抖动。Reduce Motion 下保持相同行为。
- 工作意图进入 Task Runtime 时，服从 Task / Action 事件，不伪装为聊天流式回复。

## 6. 空状态

空状态必须包含标题、原因和一个上下文相关的下一步。不得使用装饰性插画代替解释。

| 场景 | 标题示例 | 下一步 |
| --- | --- | --- |
| 尚无员工 | 还没有 AI 员工 | 新建 AI 员工 |
| 尚无会话 | 和 Alex 聊聊 | 聚焦 Composer |
| 尚无工作 | 还没有工作记录 | 前往员工会话 |
| Runtime 未接通 | 尚未接通 Runtime | 重试连接或前往设置 |
| 搜索无结果 | 没有匹配结果 | 清除搜索 |

搜索无结果不得伪装成数据为空；清除筛选后必须恢复原列表。

## 7. 错误与恢复

错误文案按以下顺序组织：

1. 失败对象，例如“无法读取员工”。
2. 影响，例如“现有会话没有被删除”。
3. 原因，使用可理解的 Runtime 信息，禁止只显示错误码。
4. 恢复动作，例如“重试”“前往设置”“重新选择文件”。

规则：

- 列表加载失败只重试该列表，不清空其他已加载页面。
- Artifact 打开失败保留 Artifact 信息，并允许再次打开或在 Finder 中定位。
- 保存失败保留用户输入。
- Tool 或 Action 失败不得自动重放整个 Task。
- `result_unknown` 只提供人工核验路径，不提供自动 Retry。
- 删除、停用、解绑和权限变更继续使用系统确认与上下文错误，不使用自动消失提示。

## 8. 表单与行内验证

### 8.1 验证时机

- 用户离开字段后显示格式错误。
- 点击保存时显示所有阻塞错误，并聚焦或导航到第一个错误字段所属区域。
- 用户修正后立即移除对应错误。
- 不在输入第一个字符时显示错误。

### 8.2 员工字段规则

| 字段 | 规则 | 行内错误 |
| --- | --- | --- |
| 员工 ID | 3–64 字符；保存前规范化为小写连字符 | “员工 ID 需为 3–64 个字符” |
| 姓名 | 去除首尾空白后非空 | “请填写员工姓名” |
| 岗位 | 去除首尾空白后非空 | “请填写员工岗位” |
| 部门 | 去除首尾空白后非空 | “请填写所属部门” |
| Identity | 去除首尾空白后非空，最多 8000 字符 | “请填写身份提示词”或长度错误 |
| Soul | 去除首尾空白后非空，最多 8000 字符 | “请填写灵魂提示词”或长度错误 |

### 8.3 API Key

- 空值不提交。
- 保存中禁用重复提交。
- 成功后清空输入并显示“已安全保存在 macOS Keychain”。
- 失败时保留输入，在字段下方显示错误。
- Secret 不进入日志、Trace、SQLite、Memory 或界面回显。

## 9. 非阻塞提示

非阻塞提示只用于复制完成、保存成功、设置更新等低风险已确认结果。

- 默认显示 3 秒，用户可以关闭。
- 错误、审批、权限、Task 失败和 `result_unknown` 不使用自动消失提示。
- 提示包含图标和文字，颜色不是唯一语义。
- VoiceOver 使用 polite announcement，不抢夺当前焦点。

## 10. Command Palette

`⌘K` 是全局键盘入口，命令按以下顺序分组：

1. 当前上下文主要操作。
2. AI 员工：开始或恢复会话。
3. 最近工作：打开对应 Task。
4. 一级导航。
5. 设置。

要求：

- 搜索员工姓名、岗位、部门、工作目标和命令副标题。
- 上下键移动选中项，Return 执行，Escape 关闭。
- 当前选中项具有背景、焦点和 VoiceOver 选中状态。
- 命令执行后关闭面板并把焦点交给目标页面。
- 不在命令面板中暴露客户端无法执行的 Package 创建或危险操作。

## 11. Hover、焦点与上下文操作

- Hover 只揭示可执行操作，例如复制、编辑、更多；不让整张 Row 上浮。
- 纯图标按钮必须提供 Help 和可访问标签。
- 键盘 Focus 必须拥有与 Hover 等价的可发现性。
- 危险操作放在 Context Menu、管理区或明确确认流程中。
- 交互目标最小尺寸为 `40 × 40pt`；紧凑 Row 内的图标可保持较小视觉尺寸，但命中区域不得重叠。
- 员工回复的“员工名 · 时间”常驻显示，并通过贯穿内容宽度的 `hairlineSoft` 细线建立轮次边界。复制和编辑操作只在消息区域 Hover 或键盘焦点时出现；隐藏不得移除可访问操作。
- 员工回复必须提供复制完整 Markdown 源内容的纯图标入口，禁止附带“复制”文字；入口遵循 Hover 显示规则，并保留 Help 和可访问标签。
- 所有消息时间必须经过统一时间格式化器，兼容秒、毫秒时间戳以及带或不带小数秒的 ISO 8601；界面禁止直接展示原始持久化时间字符串。
- 只有当前会话最新一条用户消息允许编辑；编辑器必须替换原消息气泡，确认动作使用“保存并重新发送”。Runtime 必须再次校验消息身份，删除并替换该轮旧回复，不得修改更早历史。
- 用户和员工消息超过 900 字符或 14 行时默认折叠，提供“展开完整消息 / 收起”；折叠只改变显示，不改变复制内容、可访问标签或持久化内容。
- 员工回复使用“员工名 · 时间 + 细分隔线”建立轮次边界，不新增卡片或厚重容器。
- Markdown 表格使用带表头、单元格分隔和横向滚动的原生 Grid；窄窗口不得压缩到不可读或截断列内容。
- Markdown `---` 使用左对齐的 40pt 主题色短线，禁止复用会话轮次的全宽灰色细线。

## 12. 动效

| 场景 | 时长 | 属性 | Reduce Motion |
| --- | --- | --- | --- |
| Hover / Press | 120ms | opacity、color、轻微 scale | 取消 scale |
| 面板和状态切换 | 220ms | opacity，最多 8pt 位移 | 即时切换或仅淡入 |
| 强调状态 | 350ms 上限 | opacity、scale | 禁止循环脉冲 |

- 不使用 bounce、elastic、大面积位移、视差或持续装饰动画。
- 动效必须可打断，不阻塞点击。
- 页面首次出现不批量播放错峰动画。
- 运行状态脉冲只在 Reduce Motion 关闭时显示。

## 13. Light/Dark 与表面层级

- 颜色只使用 `AppTheme.Palette` 语义 Token。
- 主区、Sidebar、浮层和输入主锚点通过背景明度层级区分。
- 主工作区保持实色；Material 只用于 Command Palette、Popover、Menu 和 Composer。
- 错误、警告、成功同时使用图标、文字和颜色。
- 数字、Token、时间和计数使用 `monospacedDigit()`。

## 14. 验收矩阵

每个新增或修改页面至少验证：

- 数据：首次加载、刷新、成功为空、搜索为空、加载失败、重试成功。
- 操作：正常提交、重复点击、提交失败、输入保留、成功确认。
- Task：running、succeeded、failed、cancelled、Action blocked、Action result_unknown。
- 窗口：`1280 × 820pt` 与 `720 × 520pt`。
- 外观：Light、Dark、跟随系统。
- 输入：鼠标、完整键盘路径、Escape、Return、`⌘K`。
- 辅助功能：VoiceOver 标签、颜色非唯一语义、Reduce Motion。

## 15. 开发检查清单

开发者在新增页面或组件前必须回答：

1. 状态来自哪个 canonical 事实？
2. 首次加载和刷新是否区分？
3. 空状态是数据为空还是搜索为空？
4. 错误影响什么，用户可以局部恢复吗？
5. 是否错误地对高风险操作使用 Optimistic UI？
6. 键盘和 VoiceOver 如何完成相同操作？
7. Reduce Motion 后功能是否完整？
8. Light/Dark 和紧凑窗口是否通过验收？
