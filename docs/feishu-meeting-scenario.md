# 飞书会议场景

范围：自然语言安排一场飞书视频会议，搜索当前组织内联系人，确认后创建会议号与入会链接，再逐人确认发送邀请。发送身份为当前连接用户。会议助理在客户端启动时安装，与飞书资料员的文档能力分开授权。

## 使用

1. 更新后重启 `npm run dev`，使主进程与运行服务加载新能力。
   开发命令默认只热更新界面，Runtime 代码变动必须停止旧进程后重新启动。2026-09-07 的修复使用 `employee-version.meeting-coordinator.v2` → `capability.feishu-meetings.v2` → `skill.feishu-meetings.v2`，启动时沿用现有内置员工升级机制；旧 Skill 和历史任务保留原版本，不能靠覆盖 v1 文件更新已安装配置。
2. 进入“连接 → 飞书 → 管理 → 开通会议能力”。沿用本机保存的应用凭证，无需重新填写 App Secret。
3. 在飞书开放平台为同一个应用开通 `vc:reserve`、`contact:user:search`、`im:message`、`im:message.send_as_user`，同时保留原文档权限与 `offline_access`。完成应用发布及需要的管理员审批。
4. 返回客户端，确认配置并执行用户授权。用户授权成功且所选权限全部返回后才保存新凭证；取消、失败或缺权限不会覆盖原凭证。原连接仅有文档权限时仍可读取文档，会议工具保持不可用。
5. 在消息中输入：“明天下午 3 点安排半小时教学研讨会，邀请本校张三。”缺少主题、时间等信息时总管先询问。姓名搜索不包含组织外好友。
6. 核对创建卡片的主题、北京时间、邀请名单，确认后生成会议。逐位核对发送卡片并确认发送。结果卡片保留会议号、链接及每次邀请状态。

## 动作与证据

| 动作 | 可接受输入 | 完成依据 | 异常处理 |
| --- | --- | --- | --- |
| 搜索联系人 | 姓名关键词；每项任务最多十次搜索 | 返回 open ID、姓名和部门 ID；显示当前组织范围 | 重名需核对，外部好友无法搜索；搜索结果不等于可发送保证 |
| 创建会议 | 主题、含时区起止时间、搜索结果中的邀请名单；最多十人 | 飞书返回预约标识、九位会议号、入会链接；原始结果摘要 Hash | 用户未确认不执行；失败不重建；超时或成功响应缺少必要字段标记结果待核实 |
| 发送邀请 | 同次运行已创建会议、已确认名单中的单个联系人 | 飞书返回 message ID；消息按实际会议结果生成 | 单次动作标识生成稳定消息 UUID；失败保留会议和已有消息；不会自动重发 |

创建和发送即使在“完全访问”模式下也需要具体动作确认。联系人、邀请内容不能通过任意消息正文、外部 URL 或模型编造的会议号绕过绑定。邀请发送不代表对方已读、已接受或实际参会。

“仅本人参会／就我自己”按仅创建会议办理，不查找“用户本人”，不额外要求给本人发消息。邀请同事时使用当前连接的飞书用户令牌发送，创建确认名单和逐人发送确认仍须完成。总管验收读取会议号、预约标识、确认名单及消息回执；同次运行返工继承这些记录，只补充尚未尝试的邀请或结果说明，不重建会议、不重发已发送或结果未知的邀请。已创建会议的事项后续失败时，界面保留可用会议结果并隐藏通用重试入口；历史审计记录不改写为成功。

## 首版边界

- 本能力创建视频会议预约，不创建日历日程，不查询忙闲，不预订实体会议室。
- 开始时间用于邀请中的时间约定；结束时间同时用作会议号到期时间。会议时长限定不超过 24 小时，预约到期时间不超过未来 30 天。
- 预约标识不是开会后产生的 meeting ID，九位会议号用于入会。
- 搜索只能发现当前组织内用户；消息能否发送还取决于飞书应用权限及平台限制。组织外好友可由用户手动转发实际会议链接。
- 修改、取消会议、重新发送失败邀请、结果未知的自动对账、日历邀请、会后纪要不在本次能力中。已有外部写入的事项不能通过通用重试静默再创建。
- 消息权限包含飞书要求的 `im:message`；应用只提供固定会议邀请发送动作，没有开放聊天历史读取或任意消息发送。

## 验证与来源

自动测试使用模拟飞书接口，不向真实联系人发消息：覆盖权限 opt-in、旧文档授权保留、搜索范围、时间校验、创建请求、稳定消息 UUID、收件人与会议绑定、确认门禁、拒绝、结果未知防重试、任务编排及客户端结果展示。

当前连接仅有文档相关权限；真实飞书创建、实际联系人触达及真实模型会议路由仍须开通会议权限后验证。不得将模拟回执作为真实创建或发送成功的证据。
