# 会议专家团 · 飞书妙记摘要 Web 原型 0.1

## 范围与入口

这是用户消息时间线的交互原型。没有意图识别、自动事项归类或追问；用户明确选择会议专家团并提交一次结构化表单，后续自动演示。

默认消息页、新建会话、通讯录的“会议专家团 → 选择并进入会话”均打开飞书会议组件。其他专家团保留原有手动消息原型。

人员为虚构示例，会议回执、飞书妙记和摘要全部来自本地数据；专家团协作为确定性的本地流程演示。不会调用飞书、发送邀请、连接 Runtime 或调用模型。真实客户端已有创建会议能力，飞书妙记读取和专家团执行服务未因本次原型开发接入。

## 状态与时间线

| 阶段 | 自动触发与处理 | 时间线留存 |
| --- | --- | --- |
| 待填写 | 用户填写主题、开始/结束时间，多选参会人，提交一次 | 唯一一条用户提交快照；默认自动录制、会后摘要 |
| 预约会议 | 演示预约会议并开启 `auto_record` | 会议编号及预约回执 |
| 发送邀请 | 演示向每位参会人发送主题、约定时间与入会信息 | 逐人邀请回执 |
| 会议开始 | 演示开始通知，关联预约与实际会议 ID | 会议已开始 |
| 录制开始 | 演示录制开始通知 | 自动录制已开启 |
| 会议结束 | 演示会议结束通知 | 等待录制文件处理；此时没有妙记内容或摘要 |
| 录制就绪 | 演示录制就绪通知，获取录制来源并关联妙记 | 统一详情展开，包含妙记来源标题和会议时间 |
| 妙记转写 | 演示首次读取返回内容未就绪，等待并自动重试 | 等待妙记转写记录 |
| 读取完成 | 重试后加载本场会议的示例转写 | 调取完成提示，不展开原文 |
| 专家团协作 | 会议纪要 Agent 整理概述与结论，行动项跟进 Agent 核对分工，会议策划 Agent 核对来源 | 开始协作与初稿核对记录 |
| 统一交付 | 三位专家完成整理和核对 | 专家团完成记录与摘要文档卡片，可预览、下载 |

预约 ID、实际会议 ID 和本地请求 ID 分开保存。实际会议 ID 只在会议开始后产生；妙记只在录制就绪后关联，内容只在转写完成后读取。未读取、来源关联其他会议、内容为空或专家团不匹配时不生成摘要。负责人须属于参会人员，截止时间须能在对应妙记片段中核对。生成文档必须等三位成员完成整理及核对。

自动演示约 30 秒，时间已压缩，不等待表单约定的真实会议时间。由 App 持有会话状态与定时器；切换菜单、会话或同时开启多场会议，不会重启或中断已有流程。每个会话按自己的到期时间推进，重复时钟检查或阶段事件不产生重复记录。全部完成或 App 卸载后释放定时器。刷新重置全部演示。

右侧展示 8 个流程节点和专家团成员状态；已经发生的节点可点击定位。底部持续显示当前状态和“自动演示中/演示已完成”，没有“模拟结束”“调取妙记”“生成摘要”等逐步推进按钮。查看历史时不强制滚动，可以使用“查看最新进度”回到末尾。表单错误在字段旁提示并聚焦首个错误。

## 飞书接口对应关系

以下为流程设计参考，原型仅按顺序演示这些结果，没有发起网络调用：

- [预约会议](https://open.feishu.cn/document/server-docs/vc-v1/reserve/apply)：预约回执不等于实际会议；`auto_record` 启用自动录制。预约 `end_time` 是预约到期时间，不能用于判定会议实际结束。表单中的开始/结束时间表示约定会议时间，由邀请传递；此原型不创建日历日程。
- [发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)：向所选人员发送参会邀请，并保留每人的消息回执。
- [会议开始通知](https://open.feishu.cn/document/server-docs/vc-v1/meeting/events/meeting_started)与[会议结束通知](https://open.feishu.cn/document/server-docs/vc-v1/meeting/events/meeting_ended)：关联实际会议并推进会中/会后状态。
- [录制就绪通知](https://open.feishu.cn/document/server-docs/vc-v1/meeting/events/recording_ready)与[获取录制文件](https://open.feishu.cn/document/server-docs/vc-v1/meeting-recording/get)：会议结束不代表录制文件就绪，需单独等待并获取妙记来源。
- [获取妙记转写](https://open.feishu.cn/document/minutes-v1/minute-transcript/get)：保留发言人与时间戳；`2091003` 内容未就绪时等待重试。真实接入需要内容导出权限；无导出权限、无录制等结果不能当作成功。

真实后端仍需做事件验签、按实际会议 ID 关联结束/录制通知、处理事件重复和乱序、权限失败与无录制的恢复。本次原型只演示成功主流程和一次转写等待，不声称实现上述真实接入能力。

## 字段与结果

- 主题必填，去除首尾空格后最多 100 字符。
- 时间统一使用北京时间（UTC+8），开始晚于当前时间，结束晚于开始，时长不超过 24 小时，结束在未来 30 天以内。
- 参会人至少 1 人，按 ID 去重、最多 10 人；当前目录提供 6 位示例。同名人员通过部门与职位区分，支持搜索、勾选和移除。
- 飞书妙记来源对象包含 provider、演示标识、会议 ID、标题、会议时间、读取时间与内部转写。来源在录制就绪后关联，转写就绪后加载本地示例内容。摘要必须消费当前会议已读取的妙记；禁止混用其他会议来源。所有结论和行动项在内部保留来源片段关联。
- 专家团和三位成员身份复用 `ExpertGroupDirectory`。会议策划 Agent 筹备会议、关联妙记、核对来源；会议纪要 Agent 调取妙记并提炼概述和结论；行动项跟进 Agent 核对负责人、截止时间和后续动作。
- 会话、摘要与每条协作记录绑定专家团或具体成员；摘要和会后协作记录使用相同的妙记来源 ID。消息统一使用“会议专家团”身份，右侧成员列表显示分工与最近完成状态。
- 消息中不展示会议原文、原文定位入口或摘要正文，仅保留进度记录与摘要文档卡片。
- 摘要生成为 `.md` 文档，包含演示说明、飞书妙记来源、交付团队与成员、会议时间、参会人、概述、结论与行动项。附件统一使用“打开方式”菜单，提供“预览文档”和“下载文档”。预览使用独立弹窗；下载保存相同内容，不附加原始发言。文档文件名由会议主题生成，替换文件系统不允许的字符。
- 每个会话独立保存会议表单、快照、事件、妙记、专家团协作记录及摘要，切换菜单或会话后保留；刷新页面重置。

## 组件与验证

消息外层、身份、时间、正文、状态和附件直接复用当前客户端组件：

- `ChatMessage`：用户消息、专家团表单消息、流程回执与最终交付。
- `MarkdownMessage`：用户提交的主题、时间、参会人员与办理设置；对动态文字转义，保留原始输入含义。
- `MessageActionCard`：表单及底部提交操作，提交按钮使用共享 actions 插槽。
- `ChatContentBlock` + `StatusLight`：过程和交付的标题、说明、阶段状态；预约信息、邀请回执、妙记来源和协作记录使用统一详情展开。
- `MessageAttachmentGroup` + `AttachmentOpenMenu`：摘要文件，Web 使用 `openMode="preview"` 和下载回调。桌面端原有系统打开与 Finder 行为保持默认。
- `MarkdownContent` + `ClientModal`：独立摘要预览。

业务页面不手写附件行、会议资料卡或协作记录卡，不覆盖共享动作卡、消息正文、状态和附件样式。会议表单字段、场景布局与右侧流程导航样式限定在 `.feishu-scene` 内，沿用排版和图标 Token。
